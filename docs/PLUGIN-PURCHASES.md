# 通用插件付费工作流：进行中

目标是让通用 JSON/JavaScript 插件实际进入预算、托管、独立验收、付款/退款和成果依赖链路。现有免费插件作业仍不拥有钱包或支付权限。此文档明确区分已实现基础与尚待完成的整体交付；公网、DON 和托管调度验收暂缓。

## 已实现并正在验收的授权基础

Vault 会话可以显式声明 `pluginPermissions`，每项绑定 `pluginId`、`manifestHash`、`runtimeHash`、`maxPriceCents`。数组必须唯一且规范排序，最多二十项。API 核验当前工作区已安装代码、实时运行时和工具声明；价格上限不得超过单笔额度。SDK 在任何钱包写操作前验证参数，在签名前检查服务端返回的完整权限集合，拒绝额外或修改的权限。

权限写入原有会话签名中的完整 Grant。历史会话没有此字段，不能因此获得插件支付能力。代码、运行时或价格变化需要明确匹配的授权；身份、期限、撤销、单笔和总额限制继续有效。这些插件细则由应用执行，现有 Vault 合约仍只执行其链上收款方、执行者、金额、期限和 epoch 限制。

新协议校验一至八步的有界 JSON 程序，拒绝未知字段、前向依赖、原型路径和超额费用。步骤输入可以选择原输入或先前已付款输出的有界对象路径；该辅助函数本身不证明付款，未来执行器必须先从规范链上凭证构建可用父成果集合。

紧凑的付费工作流引用预留全部剩余费用，并保留已注资尝试的累计会话消耗。它们接入既有订单/工作流的共享额度计算；退款不恢复会话总额，取消的未发送步骤可以释放预留，可能已广播的注资意图继续占用额度。完整付费工作流记录和执行器尚未落地，这些类型与计算不代表已有实际插件采购。

## 尚待完成的交付与验收要求

1. 新增 D1 付费工作流侧表与完整状态机，manifest/runtime/价格/输入/会话固定；同一次 CAS 预留各插件运行次数、全部采购费用及持久作业。并发和丢响应不得重复消费额度或创建工作流。
2. 每一步先持久提交注资意图，再调用 Vault；重查唯一 Opened 事件、完整托管参数和规范回执后才允许插件执行。失去广播响应必须恢复原意图，不能假定没有付款。通用 JSON 不转换成虚构转账记录。
3. 为付费执行绑定可信运行时交付身份，独立验收完整代码/输入/输出/调用记录；不能仅信任 `accepted: true` 或可自行重算的摘要。独立验收不冒充任意业务语义证明，MCP 数据源真实性需保留其信任边界。局部测试 forwarder 与实际 DON 明确分开。
4. 在真实本地 EVM 完成托管付款、错误输出退款、撤权/取消、期限退款及并发恢复。已经付款的上游成果只有重新核验规范回执后才能成为下一步输入；保留原付款 hash，失败不重购已接受成果。
5. 接通 owner API/SDK、现有持久消费者、双语审阅与历史界面。只读查询不能创建采购；草稿/同编号重试在刷新后保持。免费插件入口和旧付费技能链路维持各自原有语义。
6. 完成实际 HTTP/D1/SDK/QuickJS/MCP/EVM 集成、浏览器交互和必要回归后提交。再把新演示加入完整序列，运行全部本地 demo；阶段性授权检查不替代这条最终关卡。
