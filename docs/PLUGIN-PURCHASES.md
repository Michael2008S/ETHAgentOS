# 通用插件付费工作流

通用 JSON/JavaScript 插件现已接入持久采购、Vault、托管、签名交付、独立重放和付款/退款核心。API/SDK 与消费者已接通；浏览器付费入口和最终整套 demo 仍在进行。公网、实际 DON 和托管调度验收按用户要求暂缓。

## 授权与资金边界

免费插件作业不拥有钱包或支付权限。付费控制器先预留费用、核实实际注资，才允许 guest 执行；guest 仍只能使用已审阅的只读 MCP 工具。

Vault 的可选 `pluginPermissions` 每项绑定 pluginId、manifestHash、runtimeHash、maxPriceCents。最多二十项、唯一且规范排序。API 核验 owner 已安装代码和当前工具声明；SDK 在任何钱包写操作前验证参数，在签名前逐项检查完整权限。历史签名没有此字段，不能自动取得插件支付权。单笔、会话总额、UTC 日额度、收款方、期限和 epoch 继续约束资金；插件细则由应用执行，现有合约不声称独立解释工作区会话。

本地运营者用 AGENTOS_PLUGIN_PURCHASE_PRICE_CENTS 配置每次固定费用，默认为 100 个测试代币分。API 固定实际报价和收款方，不接受调用者提供的执行端点或任意收款地址。费用不得超过每步及总预算、签名中的插件单价和 Vault 限额。模型账单和交易 gas 不计入该代币服务费用。

## 持久性和恢复

一份程序有一至八步，输入可取原始有界 JSON 或前序已付款输出的对象路径。不会把通用数据转换为虚构转账记录。每步开始前重查原上游交付及规范付款；本地独立结算端还会用其已验收成果核对派生输入。

`agentos_plugin_purchases` 侧表存完整程序和检查点，主工作区只存紧凑引用。创建的同一次 D1 CAS/batch 固定 manifest/runtime/价格/输入/会话，预留全部费用、全部插件运行次数、未来作业槽和持久队列作业。失败的 CAS 不消耗次数，丢创建响应按同一 UUID 返回原工作流，即使此时服务离线也不重新采购。最多二十份工作流，免费/付费共享一百个已创建及预留插件作业槽。

四分钟控制租约和独立 guest 租约约束并发与迟到写入。先持久提交不可变注资意图，再向 Vault 发送原意图；丢广播响应后查唯一 Opened 事件与完整托管参数，不能假定未付款。只有实际已确认的资金凭证才能创建付费 guest 作业；原授权 epoch 失效后新授权不能复活旧预留。

取消未发送步骤释放费用及未来槽；插件运行次数不回补。可能已广播的意图继续占用费用，直到发现规范注资并退款，或取得链上期限后的未注资证明。退款回 Vault，但不恢复签名会话及链上日额度。退款尝试也保留为本工作区当天的保守费用消耗。停止、撤权或失败阻止依赖采购，已经付款的原成果及凭证不被改写。

结算意图在发送前固定。取消不能撤销已经批准且可能上链的原结算；恢复必须先读回其真实结果，而不能发送相反的报告。交易和 D1 不是一个原子事务；此实现使用不可变意图、规范回执和租约补偿该间隙。

## 交付签名与独立验收

执行服务生成专用交付签名身份，保存在其私有日志目录的 `.delivery-signer.key`。它不是买方/执行者资产钱包，不给它充值。创建采用临时文件和原子链接，权限为 0600；拒绝符号链接、宽权限和损坏文件，不静默替换密钥。私钥不会进入 guest、环境、API、manifest 或凭证。只公开 signer 地址，并把它纳入完整 runtimeHash。

服务在权限检查和实际执行后，签署绑定 runtimeHash 与完整 execution digest 的域隔离消息，并原子保存签名凭证。重启保留身份和凭证，丢响应恢复不再调用 MCP。身份/源码/工具变化导致 runtimeHash 改变，需要新的明确授权。历史未签名免费凭证仍可按原版本检查，不能作为付费验收依据。

付费验收采用 `replay-and-reviewed-verifier.v1`：先核对买方承诺的 runtime 和签名，再在新 QuickJS worker 中重放提交的代码、输入及有序工具记录，并重新运行 owner 审阅的 verifier。输出、调用参数、调用顺序、完整记录和 verifier 结果必须相符。仅重算摘要、伪造 accepted 或用有效服务签名提交不同于代码的输出都不能付款；未承诺的凭证附加字段也被拒绝。

该政策要求在固定输入和工具记录下可重放的程序。依赖随机数或当前时间而无法重现的输出会拒收。重放不会再次调用远端 MCP，因此原数据源真实性仍依赖已授权服务的认证记录；它不是任意业务语义证明、TEE、zkML 或 DON 证明。owner 的代码和 verifier 仍需审阅。

## 本地 EVM 与公共边界

本地链的专用路由重新验证完整 owner 会话签名、代码、输入、价格、部署和父付款，再调用真实 AgentVault/AgentEscrow。独立重放后用本地测试 forwarder 付款或退款，完整签名交付的哈希进入链上结果。期限退款使用合约原有路径。

该本地 EOA 验收 authority 不是 CRE DON。公共模式明确拒绝新通用插件采购，不会把旧确定性 CRE 验证器冒充为通用 JavaScript 验证器，也不会广播公共链交易。旧的转账技能工作流及其 CRE 协议保持原语义；新通用 JSON 工作流共享实际 Vault、托管、会话、预算和队列。

## API、SDK 和验收

- GET /api/plugin-purchases：只读紧凑历史；runtime=1 显式发现配置；id=... 读取 owner 的完整程序和 guest 凭证，不执行或续期。
- POST /api/plugin-purchases：create/cancel/recover，严格 schema、同源、owner、请求大小和预期 scope 约束。消费者凭证不能访问 owner API。
- sdk/plugin-purchases.ts：AgentPluginPurchaseClient，检查原草稿/完整条款/输入/付费输出/签名/工作区；可绑定 AgentWalletSession 从可信 RPC 独立复核真实付款和退款。内部租约、注资 token 不返回 API。
- `npm run demo:plugin-purchases`：实际 HTTP/D1/SDK/QuickJS/MCP/Vault/EVM，覆盖丢创建响应、两步实际付款、规范父成果、真实 MCP 快照、拒收退款、未发送取消、跨工作区/同源/消费者权限拒绝、独立消费者只靠队列完成付款、费用和余额及空队列。

原始失败记录保留：Node strip-only 不支持 SDK 参数属性，改为普通字段并增加独立导入测试；Workers 不接受 error redirect 模式，改为 manual 并拒绝非成功响应；CAS reducer 曾修改同一对象导致条款比较无效，改为提前冻结规范字节并传入克隆；凭证附加字段的可塑性用先失败的用例复现后收紧形状。第一次 HTTP 未发送注资的原意图已取得期限后的链上未注资证明并关闭，未清空历史。

当前依据见 ROADMAP-IMPLEMENTATION.md 及 outputs/validation-plugin-purchases-2026-10-22/。阶段性回归不替代新的完整演示关卡。
