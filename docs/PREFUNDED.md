# 先注资、再执行

链上订单使用独立的支付模式，状态保存在同一用户工作区 D1 中。它复用现有技能和权限控制，支付来自真实 ERC-20 托管，不扣除 testUSD 沙盒积分。原有沙盒任务和已完成成果的独立托管功能保留。

## 执行链路

1. 创建订单，固定服务报价、输入哈希、区块范围、买方、部署和证据 URL。此时为 Awaiting funding，output 为 null，成果 HTTP 地址返回 404。
2. 买方钱包批准准确代币数量并调用 `openTask`。单纯广播注资不会启动适配器。
3. 买方签署绑定工作区、订单承诺和注资交易的五分钟挑战。服务端独立验证签名、部署、金额、specHash、历史规范区块与 Opened 事件，再检查当前托管状态。
4. 只有当前仍 Funded 且未到期，才会排队执行。已退款或过期的注资只进入退款对账，不生成成果。授权后即使页面关闭，服务端后台与恢复 worker 都可继续。
5. 服务端逐阶段检查技能权限、预算和链上订单的每日额度。它读取冻结输入、执行确定性适配器并独立复算；失败会记录明确的拒绝成果。
6. D1 CAS 在最终结算检查点再次检查权限，固定不可变报告成果与 policyHash。此检查点是授权边界：之后的取消返回 409，权限变更不会追溯取消已提交的结算请求。重试复用这份请求，避免网络中断后改写已发布成果。
7. 本地模式通过实际 HTTP 发布成果，并调用临时链的 EOA 校验器：成功付款；拒绝交付退款；链上过期则调用 `refundExpired`。这是本地测试结算，不是 CRE DON。
8. 服务端复核实际 Settled 回执与成果哈希后，保存到订单和链上凭证历史。付款后 D1 写入失败时，下一次先读取终态并复用原交易；不会再付款。中断演示在已付款状态暂停，恢复只补最终检查点。

RPC 持续失败时，有界重试保留原检查点，并保存脱敏的 `lastError` 供页面显示；恢复后继续同一订单。不会把供应商 URL 或凭证放进客户端错误消息。真实 EVM 单测验证故障期间零执行、恢复后完成付款，以及错误提示在完成后清除。

每日额度按链和代币分组，计入已付款金额与在途已注资订单。它与沙盒额度分别计算；两者不能当作可兑换资金。失败订单只有读到实际退款回执后才标记 Refunded。

## 运行

启动网页与 `npm run chain:local`，运行 `npm run demo:prefund`。独立测试工作区实际经过 HTTP 钱包签名、D1、后台执行和 EVM：成功、越权、错误交付、中断恢复、注资后过期才确认五场景。每场景验证未注资零执行、错误签名、跨工作区拒绝、五次重复对账和单个 Settled 事件。

浏览器：钱包与托管 → 连接本地测试钱包 →「预注资智能体执行」→创建订单→「注资并授权执行」。订单到达 6/6 后可查看成果、检查点和真实付款哈希；刷新后保留。遇到钱包广播后页面中断，可粘贴已有注资哈希并确认，避免再次注资。

代码入口：`sdk/orders.ts`、`lib/agentos/orders.ts`、`order-chain.ts`、`order-runner.ts`、`order-runtime.ts`、`app/api/orders/route.ts`。`POST /api/runtime` 同时恢复沙盒任务与链上订单。订单上下文、原始证据和报告字节通过 owner 隔离的 `/api/orders?id=...&kind=dataset|artifact` 导出。

## 公共测试网边界

服务端仍需配置 `AGENTOS_CHAIN_CONFIGURATION`，与钱包公开部署一致。公共模式需要在注资前发布原始输入，执行后发布导出的不可变成果，并由实际 CRE 执行结算；随后在订单中粘贴结算交易哈希复核。服务端不持有生产签名密钥，也不将本地 EOA 当成 DON。公共 Sepolia 的扩展签名、真实发布服务和 DON 尚未验收。

持续链重组监控、外部供应商执行与托管环境独立持久队列仍待完成。当前适配器未调用 LLM。
