# 身份绑定与已付款信誉

本地 EVM 使用固定提交的官方 ERC-8004 IdentityRegistryUpgradeable / ReputationRegistryUpgradeable，而不是用前端计数模拟注册。源码与来源保留在 `contracts/vendor/erc8004/`，OpenZeppelin 固定为 5.4.0。两个实现通过 ERC1967 代理部署；`IdentityBootstrap.sol` 仅为本地测试设置管理员，然后调用官方 v2 初始化器。此部署不是公共网络注册表。

## 实际演示

保持 `npm run chain:local`、`npm run model:local` 与端口 5177 的网页服务运行：

1. 智能体页连接「本地供应商钱包」，选择 Atlas，点击「注册并绑定身份」。
2. SDK 注册身份 NFT，取得 token ID 后用 `setAgentURI` 补齐注册文档的 `registrations` 自引用；然后签署工作区绑定挑战。中途失败可重试，SDK 先查已有注册事件及当前持有者，补齐原交易，避免常规重试重复注册。
3. 钱包页连接买方钱包，创建新的预注资订单，可选择真实 Qwen 模型。服务端从当前链上状态复核身份，冻结身份快照和模型描述，再由买方确认注资与授权。
4. 订单 Paid 后展开「已付款订单评价」，输入 0–100 分。评分和最小付款证明将公开写入信誉注册表；原始转账数据、提示词和工作区明文 ID 不随评价发布。
5. 回到智能体页查看当前工作区的有效评价条数与平均分。原评价者可以撤销，或在订单页对账同步外部撤销后的状态。

`npm run demo:identity` 在独立工作区实际验证六组场景：注册与持有者签名、跨工作区/错误签名/并发重放拒绝；已付款评价及唯一记录；评价撤销；退款订单拒绝评价；身份转移后的失效；重新注册新身份后的恢复。每次保存完整证据到忽略的 `outputs/identity-demo-*.json`。

## 验证边界

- 服务端 RPC、chainId、身份/信誉注册表地址来自可信部署配置，调用方不能覆盖。检查合约代码存在、信誉表关联的身份地址、交易成功、确认数、规范区块哈希、Registered/NewFeedback 事件和实际链上状态。
- 注册文档采用链上的 base64 data URI，不获取用户指定远程 URL。文档包含名称、描述、技能、工作区摘要和本地 Agent ID；服务端要求文档与此档案精确匹配，不能拿另一工作区或另一 Agent 的注册交易直接绑定。
- 一次性签名绑定工作区摘要、注册表/token、持有者、收款钱包、文档摘要、随机 nonce 和五分钟期限。只接受注册身份当前持有者的签名；收款钱包读取注册表中的实际非零地址，并固定在身份快照和订单中；独立供应商可以使用不同收款方，内置执行仍使用默认收款方。支持 viem 的 EOA/ERC-1271 签名验证，实际浏览器扩展与智能合约钱包尚未验收。
- 每个新订单固定身份快照，并包含于买方授权承诺。旧订单不追溯追加身份；未付款、退款、无身份快照的订单不能进入已付款信誉。已注册身份被转移、收款钱包清零或 URI/持有者改变时，新订单会被拒绝，需要重新核验/绑定。
- 评价必须来自原买方，付款回执重新从 RPC 核验，卖方必须匹配身份钱包；持有者和已授权 operator 均不能自评。NewFeedback 的评分、原买方、身份 token、订单标签、文件 URI 和 keccak256 内容摘要必须精确匹配已提交意图。
- D1 CAS 保证同一工作区每个订单只计一条评价；首次评分提交后固定，后续只能对账或撤销，不能用新分数覆盖。SDK 重试先查链上事件，避免已上链后的普通重放再发交易。
- 官方信誉表是开放协议，本身不要求付款、也不保证每订单仅一个事件。外部用户可直接提交其他反馈；AgentOS 不将这些反馈直接计入工作区评分。跨浏览器同时签署同一评价仍可能产生重复链上事件，工作区只接受一个回执并计一次；没有声称全网信誉防女巫或全局严格一次。
- 身份和反馈显示的是已核验检查点，手动重新核验/对账会读取当前链上状态。持续链重组监控与全网索引仍待实现；原型依赖可信 RPC 和受信任的服务端配置，不提供防运营者篡改的 D1 证明。

## 配置与 API

生产环境复用 `AGENTOS_CHAIN_CONFIGURATION` 的可信 RPC 与部署配置，在 `deployment` 中增加 `identityRegistry`、`reputationRegistry`。两者必须实际部署并相互匹配；不能把本地地址用于 Sepolia。当前私有站点未配置这些公共网络地址，因此不显示可用的注册钱包操作。

- `GET /api/identity`：当前 owner 的绑定与评价凭证、公开部署信息。
- `POST /api/identity`：prepare / challenge / bind / refresh / feedback-prepare / feedback-confirm，均有同源、认证、严格字段和长度限制。
- `sdk/agent-identity.ts`：注册、恢复注册、签名绑定、评价及撤销；不保存私钥。
- `sdk/orders.ts`：新订单由服务端选择已核验身份，客户端不能伪造身份快照。

本地提供商 RPC 只允许供应商账户向身份注册表发送交易及签署限定前缀的绑定消息；买方 RPC 只允许其测试 token、escrow、信誉表。买方及两个供应商测试钱包均为临时链自动生成，不能用于真实资产。重启测试链会创建新的部署，D1 的旧历史保留为原部署证据。

规范与实现：[ERC-8004](https://ercs.ethereum.org/ERCS/erc-8004)、[固定提交的官方源码](https://github.com/erc-8004/erc-8004-contracts/tree/b9e466c250744a7e06b13dff9d3c2844ed64f825/contracts)。
