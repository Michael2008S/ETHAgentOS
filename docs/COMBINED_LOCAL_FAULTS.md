# 同一工作区的组合故障验收

`npm run demo:combined-faults` 同时保持三类真实本地故障：CCIP B 链已结算但结果消息延迟、USDC/USD Mock Feed 脱锚、x402 上游交易已挖出但调用方不能读取其收据。它们存在于同一 SQLite/D1 工作区的任务状态中；链、Token 和 Vault 仍独立。

实际断言：

1. CCIP D1 预留 100 分，A/B 各保留 1,000,000 最小单位；结果未决不会被另一采购的失败释放。
2. x402 采购本金 200,000 最小单位与未知原生 gas 上限继续占额，原 nonce 不变；Feed 异常阻止新采购。
3. owner 取消后用户本链 Escrow 可以全额退款，供应商承担的未知上游成本仍占额，不能将两者混算。
4. 恢复收据观察、Feed 仍异常时，用不签名、不广播、不创建新授权的 `reconcilePending()` 对账。上游付款事件恰好一次，供应商支出 200,000，未知预留清零；用户退款保持原交易。
5. 解除 CCIP 结果延迟，结果及 ACK 完成后才释放 CCIP 对应预留；最终原生 gas 也对账为一笔交易。

`tests/combined-faults.test.mjs` 调用同一生产状态机与验收程序。实现新增的只读采购对账入口不受新采购的最新 Feed 风控阻断，且不放宽任何支付授权。真实 Feed、真实 CCIP 与真实资产均未参与。
