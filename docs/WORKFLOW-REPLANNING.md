# Reviewed replanning of unfinished workflows

AgentOS can generate a replacement program for unfinished work, preserve already-paid accepted results, and start only the newly reviewed purchases. This extends initial goal decomposition: a replacement may contain 1–8 steps and can reference any available paid result in its bounded ancestry, the original input or an earlier result of the new program. Generation is owner-triggered and approval remains explicit. Unattended failure-triggered proposal generation is not enabled by this increment.

## User flow

In the workflow planner, select an unfinished source under **Planning source**. Inspect the goal, select an active Vault session, and set both the remaining-work ceiling and the gross goal ceiling. The latter includes every earlier funded attempt, including refunded ones. Edit the remaining goal and generate a replacement plan. The editor's unrelated JSON is not used: the original source input is fixed server-side.

The review card shows the source, original goal, old funded charges, gross ceiling, combined proposed charge, retained paid results and each new step's actual input reference. Generation changes no old status, reservation, order or durable job. A fresh source snapshot, current permissions/fees, canonical paid artifacts and finalized refunds are checked before approval. Approval atomically cancels only unspent old work, links `supersededBy`, stores the new plan/workflow association, creates its first child and publishes its durable jobs. Existing paid/refunded orders, receipts and evidence remain intact.

For example, an accepted report cost 360 cents and a failed signed summary funded 200 cents before refunding. With a 1,200-cent gross goal ceiling, 640 cents remain available for new attempts. The actual model generated a one-step summary and a separate two-step summary→report program. The approved two-step program cost 540 cents, so the entire goal funded 1,100 cents. Actual net payments totaled 900 cents; the 200-cent refund returned to the Vault but restored neither the conservative goal allowance nor the signed/onchain allowance.

The default displayed goal ceiling comes from the previous approved goal or initial workflow. Raising it requires explicitly entering and reviewing the new value; no worker raises it automatically. A higher goal ceiling does not override the signed session, workspace daily cap or onchain grant. Gas and model-provider charges are separate from token service/funding ceilings.

## State, execution and API

`POST /api/workflow-plans` adds the strict `replan` action with the existing planning fields except input, plus `sourceWorkflowId` and `goalBudget`. Caller-supplied roots, input, URLs, source evidence or signatures are refused. `AgentWorkflowPlanClient.replan` provides the matching SDK method and checks the returned source, goal/limits, buyer, deployment, scope and complete digest. Existing `list`, `dismiss` and `accept` handle both ordinary and replacement proposals. Replaying an already stored request returns its original proposal; accepted approval replay returns the original replacement without another purchase. A competing proposal for the superseded source cannot be approved.

The immutable `agentos.workflow-replan.v1` context fixes source/ancestry IDs, source snapshot hash, original goal, gross spent, reviewed goal ceiling, accepted root commitments, failed/unsent attempts and step history. Diagnostic `lastError`/observation timestamps are excluded from the source snapshot; workflow/order commitments and financial checkpoints are included. There are at most eight source generations, 32 paid roots and 64 historical steps. Proposal/history/order/workflow capacity and normal memory-depth bounds still apply; exceeding a bound fails rather than silently dropping history.

The model sees the authorized catalog, goal, input metadata/hash, step history and paid-root descriptors with bounded aggregate facts. It never receives transfer rows, complete evidence files, session signatures or keys. `source: -1` selects original input; `-2` selects paid root zero, `-3` root one, and so on. Nonnegative sources select an earlier replacement step. These model indices are normalized into exact `{from:'accepted',orderId}` references in the reviewed program. Root references cannot be injected through ordinary manual workflow creation or portable templates. The runtime resolves the scoped original and verifies its full delivery/payment lineage before using it.

Outstanding funded orders or unresolved funding intents must finish/reconcile/refund first. Paid roots are independently checked against canonical settlement and their complete artifacts. Refunds use the same finality verification as automatic supplier fallback; a missing finality result refuses generation/approval. Unsigned unsent drafts require an absent escrow, and an old funding intent must be reconciled/cancelled after its deadline. A source that has no unfinished steps, is complete or has already been superseded is refused.

Capacity calculations release the old unspent reservations only in a speculative copy until approval's CAS commit. The published replacement artifact can safely survive a failed commit and be reused with identical bytes. A changed source, price, provider, policy, session or quote prevents approval rather than modifying the plan. Every new funding intent additionally verifies its approved replacement program, source linkage and all previous failed attempts' canonical refund/unsent proofs. Reused inputs retain the existing canonical parent/ancestor payment checks. Mined funding still follows normal reconciliation rules; a lost RPC response does not authorize another principal transfer.

Graph, source-replacement and session policies are enforced by the trusted application and its configured RPC/executor. CRE independently validates complete deterministic delivery and the escrow validates reports; they do not independently enforce the entire application graph or gross goal policy. Local acceptance is not proof of public Sepolia, browser-extension or registered DON operation.

## Acceptance

```sh
npm run demo:workflow-replanning
```

The actual HTTP/D1/SDK/independent supplier/ERC-8004/Vault/EVM acceptance first produced a real paid report and signed invalid-summary refund. The pinned Qwen 3B then generated two distinct one/two-step repairs with paid-root references. Tests verified no procurement before approval, gross-budget/scope refusal, lost approval response recovery, one replacement, exact new purchases, unchanged original receipts, Vault/seller deltas, one Opened event per order and a drained durable queue.

Controlled-model in-process EVM tests separately cover source drift, finality refusal both before approval and before new funding, immutable publication before failed CAS, concurrent replay, exact signed allowance after releasing only old future reservations, one-step repair from another paid root and two successive replacements that reuse an older ancestor. Five focused tests additionally cover strict API fields, bounds, pre-inference refusal, snapshot stability, input confidentiality, SDK mode/source/limit refusal and foreign/completed sources. These controlled responses are not counted as actual model inference.

The full browser regression covers persisted source/limits across reload, deliberately unrelated editor JSON, real model proposal review, zero preview purchases, lost approval recovered through history, remaining-step execution, unchanged paid/refund receipts, Chinese/English and mobile width. Final project acceptance remains a separate gate after the remaining capabilities are finished.

All six durable jobs completed with no pending/leased/dead jobs. The current 177 Node / 16 Chromium regressions, five CRE SDK tests (80 assertions), type checks and production build passed. Raw logs/reports and the reviewed mobile screenshot are retained in `outputs/validation-workflow-replanning-2026-10-22/`.
