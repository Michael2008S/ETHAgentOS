# 三分钟演示：有预算、可验证、可恢复的 Agent 采购

一句话：**把 Agent 服务采购变成有身份、有权限、有交付证据、失败可退款的执行流程。** 本轮为本地真实 Qwen、独立 HTTP 供应商及本地 EVM；CRE 是官方 CLI dry-run，不是 DON 实际执行。

## 开场前

1. 首次安装按 LOCAL-DEMO.md 准备模型和数据库，升级时应用新增迁移。
2. `npm run demo:start` 保持运行，`npm run demo:doctor` 检查依赖，`npm run demo:prepare` 准备本地测试币、身份和供应商授权。
3. `npm run demo:showcase` 创建或复用当前部署的成功/退款订单和付款评价，输出订单链接；重新执行全新订单时加 `-- --fresh`。
4. `npm run demo:cre` 单独跑三场景，准备日志；台上不要等待首次安装、下载或登录。

## 0:00–0:20 讲清问题

“Agent 会调用工具，但采购另一个 Agent 的服务时，谁有权花钱、成果是否符合约定、断线会不会重复付款？AgentOS 把这些规则放进运行时。”首页展示真实健康状态和消费者联系时间，明确区分沙盒积分与链上测试代币。

## 0:20–0:45 身份与采购建议

展示 Atlas 的 ERC-8004 身份和供应商委托。在钱包草稿中用 AI 比较服务：模型判断所需能力，运行时比较授权目录的真实报价，用户审核后采用。建议不会创建订单或付款，小模型分类仍需人工审核。

## 0:45–1:25 先承诺、再执行

固定输入，展示 Awaiting funding 时没有成果；连接测试钱包，注资并签署工作区授权。展示真实 Qwen 计划、独立供应商计算及签名交付。若时间不足，打开 showcase 成功订单链接，并明确它是演示前实际执行的记录，不伪装成现场执行。

## 1:25–2:00 一页验证为什么付款

打开统一订单证据，依次查看身份快照、输入承诺、模型记录、供应商签名、独立复算、注资和结算回执、买方评价。模型没有签名权限；模型日志、供应商签名与链上回执有不同的核验边界。

## 2:00–2:30 拒绝与恢复

展示错误交付订单：签名不代表结果正确，独立复算拒绝后退款。再展示 queue demo 的响应丢失、并发消费者和只付款一次证据。前端重试也沿用原请求 ID。

## 2:30–3:00 评价与 Chainlink 边界

展示买方评分和付款证明，再展示 CRE CLI 接受/拒绝日志。“本地链闭环与官方 CLI 模拟已验证，公共测试网、真实 DON、托管调度留到下一阶段。”

## 备用与提交材料

- 保留成功、退款、恢复、越权零付款的证据及视频。
- 提供仓库、版本、启动命令、网络/合约地址和可验证的交易记录。
- 提交前另行核验主办方当前规则；需要真实 DON 时，CLI 模拟不能替代 execution ID 与结算交易。
- 线上站点与本地代码版本可能不同，本轮不自动公开站点或开启调度，评委访问需单独安排。
